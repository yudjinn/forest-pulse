# ADR 20261114163418117 - Activities are derived on read; directions and locations are fixed at arrival

- Status: accepted
- Date: 2026-11-14
- Source:
  - feature/1#decision-11
  - feature/8#decision-1
- Scope: web/src (activities, location)

Activities are never stored: every read groups the stored events with the one 60 s merge rule, so a late backlog lands in the right activity and Clear events needs no bookkeeping (human-decided). Directions and locations are the opposite: computed once when an event arrives, from the plan's placement and online state at that moment, and stored on the event, so moving or turning a sensor later never moves a line or point already shown, and a backlog uses the placement current at delivery (human-decided). They live in nullable columns on the events row, with the line's origin stored rather than only its angle, so Clear events and every read need no second table (agent-made, survived review).

## Consequences

The activities read loads every stored event on each 2 s poll; cost grows with an uncleared log, and a time window or a stored summary is the contained fix if it ever matters. A stored direction or location cannot be recomputed for past events: there is no placement history, so fixing a wrong facing only corrects new events.
