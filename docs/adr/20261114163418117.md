# ADR 20261114163418117 - Activities are derived on read; directions and locations are fixed at arrival

- Status: accepted
- Date: 2026-11-15
- Source:
  - feature/1#decision-11
  - feature/8#decision-1
  - feature/42#decision-4
- Scope: web/src (activities, location, warnings)

Activities are never stored: every read groups the stored events with the one 60 s merge rule, so a late backlog lands in the right activity and Clear events needs no bookkeeping (human-decided). Directions and locations are the opposite: computed once when an event arrives, from the plan's placement and online state at that moment, and stored on the event, so moving or turning a sensor later never moves a line or point already shown, and a backlog uses the placement current at delivery (human-decided). They live in nullable columns on the events row, with the line's origin stored rather than only its angle, so Clear events and every read need no second table (agent-made, survived review). Anything attached to an activity follows the same rule: a warning or a dismissal stores the activity's newest event id at that moment and belongs to whichever activity holds that event on read, so it stays on the right card as the activity grows or joins another, and Clear events deletes it with the events (human-decided).

## Consequences

The activities read loads every stored event on each 2 s poll; cost grows with an uncleared log, and a time window or a stored summary is the contained fix if it ever matters. A stored direction or location cannot be recomputed for past events: there is no placement history, so fixing a wrong facing only corrects new events.

- 2026-11-15 - Context grew: warnings and dismissals attach to an activity through its newest event id instead of an activity record; the decision itself is unchanged (Source: feature/42#decision-4).
