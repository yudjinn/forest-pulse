# ADR 20261114110501527 - Server and dashboard on Cloudflare; teaching computes embeddings in the browser

- Status: accepted
- Date: 2026-11-14
- Source: human-decided
- Scope: system-wide

The sensors talk directly over the internet to the deployed Cloudflare service at forestpulse.paxid.com, which hosts the device API, the researcher dashboard and storage. No laptop server, even for the demo, so the demo is the real architecture. Workers cannot run the model, so teaching splits: the researcher's browser decodes the clips, mixes them over the hall background and computes embeddings with the ONNX model in WebAssembly (79 ms per 10 s window measured), and the Worker trains the 4 KB detector from those embeddings plus stored ones. Audio is never uploaded or stored.

## Alternatives considered

A Cloudflare Container running the Python code: works from any device, but a second system with an unmeasured cold start that could land on stage. Python Workers run on Pyodide, which cannot run the model's ML library.

## Consequences

Sensors need internet access at the venue (a captive-portal Wi-Fi blocks them). Teaching speed depends on the researcher's computer and needs the tab open until the embeddings are sent.

## History

- 2026-11-14: training moved from a Cloudflare Container to the browser plus the Worker after the ONNX export proved exact and fast in WebAssembly; removes the container and keeps audio off the server.
