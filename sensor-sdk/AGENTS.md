# Sensor library invariants

- Every request to the sensor API sends the library's own `User-Agent` (`forestpulse-sensor/<version>`, set in `api.py`). The live site's Cloudflare zone refuses Python's default `Python-urllib/*` agent with HTTP 403 (error code 1010) before the Worker runs; the library reads that as "server unavailable" and retries forever, so a board without the header never delivers. Local journeys cannot catch this: only the live edge applies the check.
- `forestpulse_sensor/data/seed_sounds.json` is the service's seeded sound list at the same version (2, since the retrained chainsaw; agent-made, confirmed by the user). A board that has never reached the server detects with it, so a migration that changes a seeded sound also changes this file, its version and the library version.
- `Api` reads the wall clock for `sent_at` at call time (`utc_now_iso()`, or the `clock` a simulated board passes). Never capture `time.time` as a default argument: the web journeys' `shifted_clock.py` patches the clock after the library is imported, and a captured one silently gives every clock-shift journey the true time.
- While a calibration run streams, `Sensor.feed()` hands the audio to the run's ring and nothing else (`Calibrator.feed`), and no sound events are queued until the report is posted. Audio that bypasses `feed()` during a run misses the ring and the run's rounds come out as dropped.
- The simulated bearing hook (`calibration/simulate.py`) finds the window it is given by matching it, sample for sample, against what the simulated board streamed, and answers only when that window covers a sweep's first path. Any conversion of the audio between `Sensor.feed()` and the calibration ring (a dtype change, a resample, a gain) makes every simulated bearing answer None, and every simulated run then fails with "couldn't tell direction".
