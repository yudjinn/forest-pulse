# Forest Pulse glossary

- **Sensor**: one deployed device: ESP32-S3 audio front-end with three microphones in a right triangle (4 cm and 8 cm sides, see soc/README.md), plus an Arduino Uno Q that runs the sound model.
- **Sound model**: EfficientAT mn10_as, identical on every sensor. Turns 10 s of audio into built-in label scores and a 960-number embedding.
- **Detector**: a small classifier trained on the embedding for one sound (for example chainsaw, boreal owl). About 4 KB as raw numbers. Alerts come from detectors.
- **Seeded sounds**: the sound list a fresh service and a new sensor start with: the Chainsaw and Gunshot detectors, trained before the demo. Any sound can be deleted, a seeded one too.
- **Built-in labels**: the sound model's own 527 AudioSet scores (Vehicle, Aircraft, Rain...). The sound list can still carry one (`kind: label`), but none is seeded: they hear the hall poorly.
- **Sound of interest**: a sound the server tells sensors to report, either a detector or a built-in label.
- **Event**: one report from one sensor: which sound, how confident, when, and its angle.
- **Activity**: what the dashboard shows researchers: a suspected situation (logging, poaching, owl present) built from one or more events.
- **Teaching a sound**: a researcher drops example recordings in the browser, which turns them into embeddings; the server trains a detector from them; sensors pull it.
- **Wake**: the ESP32 wakes the Uno Q on any sound noticeably above the background level. Always-on for the demo.
- **Researcher**: a person signed in to the dashboard.
- **Angle**: the direction of a sound relative to its sensor's board, degrees clockwise from the board's marked forward (0 to 360). Sent by the sensor.
- **Facing**: which way a sensor's forward points on the plan. Entered on the dashboard or set by a calibration run whose sensors can tell direction (a distance-only run keeps it); plan direction = facing + angle.
- **Hall background**: a recording of the demo venue that training mixes under every taught sound and uses as an example of what to ignore.
- **Calibration run**: pressing Calibrate: 2 or 3 calibration-capable sensors beep their own sweep in scheduled slots over several rounds; the service turns what each heard into distances, facings and a relative layout. A participant that never gets ready is left out and the others calibrate without it.
- **Calibration-capable sensor**: a sensor with a 3-mic array, a buzzer and a sensor library new enough to take part. A single-mic sensor or one without a buzzer is not.
- **Stage check**: recording the real buzzer on the stage at 1, 3 and 5 m and running the library's check tool on the recordings, which answers PASS or FAIL for relying on calibration at the demo.
- **Measured layout**: a plan set by a calibration run, relative to the sensors (first sensor at the origin, second to its right). A manual layout is one set by dragging and typing facings.
- **Sensor name**: "Sensor N" on the dashboard, N the lowest number not held by another sensor on the plan when it joins; a returning sensor takes its old number back when still free. A sensor not on the plan shows its own id, which still identifies it to the service. The plan lists sensors by number, so plan order is Sensor 1 first.
- **Warning**: the operator's response to a logging activity: every board that heard it plays the alarm on its buzzer, standing in for a radio warning to the loggers that logging here is unauthorised.
- **Alarm**: the warning's sound: a harsh hi-lo stutter (3.5 kHz and 2.5 kHz tones, 120 ms each, one every 150 ms) for about 5 s, unlike the smooth calibration sweeps.
- **Sensitivity**: one confidence threshold, set in the dashboard's Devices panel, that every sound of interest must reach before a sensor reports it.
- **Trigger health**: what a sensor's front-end is doing: recordings per minute (counted by the library) and, when the board provides them, its trigger values and noise floor.
- **Map**: the dashboard's tilted view of the plan: each sensor a numbered puck, rings a round number of metres apart, and each heard sound shown for 15 s as a direction or a located point.
- **Devices panel**: opened from the dashboard's top right: one tab with Calibrate, a card per sensor (its id, health, versions, facing, Remove) and the sensitivity, one with the event log and Clear events. While it is open the map tips to a plan view and sensors can be moved.
- **Pulse**: the line along the foot of the dashboard covering the last 90 s: a small beat for every sensor check-in and a spike for every sound heard.
