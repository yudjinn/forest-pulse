# Dashboard invariants

- One page, two audiences: the researchers' dashboard at `/` and the public demo at `/dashboard/`, which is the same file with `demo/demo.js` and `demo/demo.css` added by the Worker. A new control that changes anything is hidden in `demo/demo.css`, and a new data path gets a simulated reply in `demo/demo.js`, or the demo shows a broken control or an empty view (agent-made).

- Scripts load only from files: `_headers` gives `/dashboard/*` its own Content-Security-Policy after detaching the site-wide one (`! Content-Security-Policy`). Without the detach both policies are sent and enforced together, so the site-wide `default-src 'none'` and `form-action 'none'` block every script and the sign-in form. A page that needs more (WebAssembly, a worker) adds it to that one rule.
- Live views poll through `poll()` in `shell.js`, never their own timer: the connection-lost line counts failures across every poller on the page and only `poll()` feeds it.
- After a page action that changes what other views poll (Clear events), call `refresh()` from `shell.js`. A poll already in flight may have been answered before the change, and without it that reply redraws the old data for one cycle.
- The map draws only when asked (`plan/scene.js`): a module calls `invalidate()` only when what it would draw changed, and reports `active()` while it animates. An `invalidate()` on every poll reply makes an idle map draw a full frame several times every 2 s; the plan, the locations and the calibration (`plan/plan.js`, `location.js`, `calibrate.js`) each compare a key of what they draw first.
- Whatever a person or a journey must read on the map (flags, distances, a sensor's handle, measured distances) is an element in `#map-overlay`, placed with `place()`. The canvas is one image to a screen reader and to `getByRole` or `getByText`: text drawn on it cannot be found by either (agent-made).
- The buttons that open a panel or dialog (Devices, the player, the pulse, Teach a new sound) start `disabled` in `index.html` and are enabled by the module that listens to them. Without that, a press in the first moments after load does nothing, which a journey does every time.
- Teaching and the player load by dynamic import when first opened (`sounds/sounds.js`, `drawer.js`). `teach/teach.js` starts fetching the 35 MB model as it loads and `player/player.js` fetches every recording: importing either from a module the page loads at the start puts that on every dashboard load.
- The policy in `_headers` allows styles only from files too (`style-src 'self'`): a `style="..."` attribute in the page is dropped silently, while setting `element.style` from a script works. A category's icon and colour come from its `c-<category>` class in `shell.css`.
- Whether an activity alerts or can be warned about is the activities reply's `alert` and `warnable`, judged on the service clock; the dashboard never works either out from times. Every Send goes through `sendWarning` (`activities/warnings.js`), keyed by the activity's newest event id: a second Send path keeps a request id of its own, so a retry after a lost reply can send a second warning (agent-made).
